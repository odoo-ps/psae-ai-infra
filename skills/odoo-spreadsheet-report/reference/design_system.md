# Spreadsheet Report — Design System

Canonical layout, sizing, palette, and styling reference for dashboards generated by `odoo-spreadsheet-report`. Read once before composing a sheet; consult when laying out scorecards, charts, or multi-section dashboards.

Companion to [`troubleshooting.md`](troubleshooting.md) (symptom → cause → fix), [`cf_operators.md`](cf_operators.md) (conditional-format + global-filter operator registries), and the canonical `.osheet.json` samples under [`samples/`](samples/). The production-readiness checklist that *verifies* compliance with this document lives in [`SKILL.md` § Design System](../SKILL.md).

---

## Layout discipline (single-screen, low-cognitive-load)

- **Single-screen rule.** A presentation sheet should fit a typical laptop viewport (≈1320 × 700 px) without horizontal scroll and minimal vertical scroll. Aim for `colNumber=12` × 110 px = **1320 px wide** as the canonical dashboard width. Don't choose 24-col grids unless you actually need 2× density.
- **Sizing budget — fit, don't fill.** Oversized scorecards are a classic mistake. The eye registers a KPI in 100–130 px of vertical space; anything taller becomes empty fluff. Fixed sizes:
  - Scorecard: **220 × 110** (single-line value) or **220 × 130** (with prominent baseline).
  - Compact bar / line: **660 × 280**.
  - Detail bar / line: **660 × 360** (only when you need axis room).
  - Tall pivot: **440 × 360**.
- **Pack horizontally before stacking vertically.** 6 scorecards in one row = scannable hierarchy. 6 scorecards stacked 2×3 = busy. Always lay out KPIs of the same tier across, not down.
- **Title bar.** Row 1, height **50 px** (not 60), merged across the full sheet width, style `1` (navy `#1F3A5F` fill, white text, fontSize 22, bold, centered).
- **Spacer rows.** **10 px** between title and content, **16 px** between major content sections. NOT more — bigger gaps create disconnected zones.
- **Grid alignment with figure widths.** Figure widths must match a whole number of grid columns at the canonical column width. On a 12-col × 110 px grid, valid widths are 220 (2 cols), 330 (3), 440 (4), 660 (6), 1320 (12). A 430 px scorecard on a 110 px grid is misaligned and looks janky next to its neighbours.
- **Figure anchors.** `col` and `row` are **0-indexed cell anchors**, NOT pixel coords. `offset.x` / `offset.y` are pixel offsets within the anchor cell. For tightly-packed grids, use offset 0 — `offset: {x: 8, y: 8}` introduces 8 px gaps that compound across rows. Reserve offsets for sheets where breathing space is the design intent.
- **Don't anchor multiple figures on row 0.** Title is on row 1 — overlapping it makes the title disappear. First content figures should anchor at `row ≥ 2`. See [`troubleshooting.md` #11](troubleshooting.md) for the symptom.
- **`rowNumber` should match content height**, not be padded: a dashboard with 35 rows of content uses `rowNumber: 36`, not `rowNumber: 50`. Excess empty rows below the content read as "report unfinished."
- **Turn off gridlines on presentation sheets.** `"areGridLinesVisible": false`. Keep them on for hidden helper sheets so debugging is easier.

## Cognitive-load discipline

- **Tier KPIs into one row each.** A dashboard typically has at most 3 tiers: top KPIs (6–8 scorecards), trend (2 charts side-by-side), distribution / breakdown (2 charts side-by-side). More than 3 tiers and the user is hunting.
- **One colour = one meaning.** Don't use the red palette for both "issue" and "vendor" decoratively. The palette below is keyed to semantics, not aesthetics.
- **No floating annotations.** "KPIs" / "Trend" / "Charts" labels in cells next to figures are noise — the figure title already says what it is. Drop them.
- **Same-tier widgets share dimensions.** All 6 scorecards in row 1 must have identical `width` × `height`. Same for all 2 charts in a row.
- **Title sizes should taper.** Sheet title 22 → section heading 16 → chart title 14 → scorecard title 12 → scorecard descriptor 10. Shouting at every level is the same as shouting at none.

## Number formats

- Currency / amount columns: `"#,##0.00"` (define once as `formats["1"]`, reuse).
- Counts: `"#,##0"`.
- Percentages: `"0.00%"`.
- Dates: `"mm/dd/yyyy"` (or locale).
- Apply formats by range, not per cell.

## Conditional formatting (always pair status with colour)

- **Status pills** (e.g. Healthy / At Risk / Over Budget): one `CellIsRule` with `operator: "isEqual"` per status value, painting fill + text from the palette above.
- **Negative markers** (e.g. AR > 90 days, count of overdue tasks): `CellIsRule` with `operator: "isGreaterThan"` and `values: ["0"]` → red fill + bold deep-red text. Zero stays default.
- **Performance KPIs**: green fill when `>= target` (`operator: "isGreaterOrEqualTo"`). Use the scorecard `baselineMode: "difference"` with `baselineColorUp / Down` rather than a conditional format when you're comparing two cells.

The full operator registry — what names are actually valid in the o-spreadsheet runtime — lives in [`cf_operators.md`](cf_operators.md) § CellIsRule operators. Always reference it; the Stage-1 verifier rejects any operator not on the registry's canonical list.

## Scorecards (the headline KPIs)

- Width 220 px (standard) or 220 × 130 (with baseline).
- Background = palette colour matching meaning (red for issues, green for healthy).
- `keyValue`: cell reference (e.g. `'Forecast Config'!B5`), not a literal.
- `keyDescr`: short noun ("Task(s)", "Hour(s)", "Net") in fontSize 11–12, centered.
- `baselineMode`:
  - `"difference"` when comparing to a baseline cell numerically (delta arrows shown).
  - `"text"` when the baseline is a label (e.g. "Hours Expected").
- Always set `humanize: true` so big numbers compress to `1.2K` / `3.4M`.

## Charts

- **Native bar / line** (`type: "bar"|"line"`) for cells you've already aggregated in the sheet — set `dataSets[].backgroundColor` for theming.
- **`odoo_bar` / `odoo_line` / `odoo_pie`** for live, drillable Odoo data — embed `metaData` + `searchParams` + `actionXmlId` (so clicks open the underlying view).
- Always set `axesDesign` with axis titles ("Week", "Hours", "Amount", "Project") — unlabeled axes look unfinished.
- `legendPosition`: `"none"` for single-series charts; `"top"` or `"left"` for multi-series.
- Fixed sizes (must align to grid column width): **compact 660 × 280** (default for dashboard rows), **detail 660 × 360** (when axis labels need room), **tall pivot 440 × 360**, **half-width 330 × 280** (only when 4 charts must fit one row).

## Sheet ordering (visible first, hidden last)

1. Headline dashboard (overview).
2. Per-domain detail sheets (e.g. Aging, Project Cash Position).
3. Hidden config / helpers (`isVisible: false`).
4. Hidden raw data lists (`isVisible: false`).

## Why these defaults exist

These dimensions are what the canonical samples under `reference/samples/` use, and what the shipped Odoo Enterprise spreadsheet dashboards (`enterprise/spreadsheet_dashboard_account_accountant`, etc.) settle on. Mirroring them keeps generated dashboards visually consistent with what Odoo users already recognise.

If you find yourself wanting different dimensions: confirm via a side-by-side comparison against a shipped Enterprise dashboard that the new dimensions are demonstrably better, not just "different because the data felt cramped." The grid is the constraint that prevents subjective drift.
